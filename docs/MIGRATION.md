# QuantSandbox 3 融合与迁移

新工作区统一承载研究与策略实验，旧研究目录保持独立。QuantSandbox 仓库以正常提交升级，历史保留；融合前基线由 `pre-fusion-20261101` 标签标记。

## 代码

React 接管统一前端。旧 Vue 源码仍可由 Git 历史恢复，当前目录不再保留第二套产品入口。原账户、撮合、策略、分叉、实验、盲测和证据逻辑继续使用 `backend/core` 与 `backend/services`。研究功能位于 `backend/workbench`，路由统一加 `/api/research` 前缀，避免两类运行记录冲突。

原策略接口路径与 v2 证据包读取保持兼容。研究项目通过有类型的记录链接关联不同计算结果。桥接将研究行情冻结为策略快照，并保存上游来源、快照 ID、哈希、价格与成交量口径；没有重新下载另一份数据。

## 本地数据

- 策略 SQLite、缓存与 Parquet 延续 `data/` 默认路径。
- 研究缓存与历史记录为 `data/workbench/workbench.sqlite`。
- 自定义策略数据目录使用 `QUANT_SANDBOX_DATA_DIR`，研究独立目录使用 `QUANT_WORKBENCH_DATA`。
- 所有缓存、记录、公司配置、附件与导出仅留本机，不随 Git 同步。

`import_research.py` 只读连接源数据库并执行 SQLite backup，兼容源目录仍在使用 WAL。只复制研究附件目录，不复制旧服务运行状态、外部交接文件、私人笔记或可执行辅助脚本。目标存在时拒绝覆盖；失败暂存留在 `.local` 以便诊断。

复制后保留原快照与记录编号、原始来源及计算版本。旧结果不会静默重新标为新公式；复算应核对归档版本与新版本输出。导出的历史原始快照可能保留原版本元数据，这是证据的一部分。

## 运行与隐私

生产端口 8766、开发页面 5174，允许旧研究服务保留原端口独立运行。启动与停止只管理本目录拥有的进程。Obsidian 配置是可选的本地设置，默认关闭，不依赖某个特定仓库名称或目录；只在显式动作下保存。

## 回滚

原目录从未原地迁移。需要回到旧策略代码，可在独立目录检出融合前标签，再恢复相应数据备份；不要在运行中的数据目录切换代码版本。升级前后备份整个 data/ 与 exports/，停止后再搬移 SQLite 文件。
